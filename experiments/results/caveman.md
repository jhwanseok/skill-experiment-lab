실험설계: [`experiments/design/caveman.md`](../design/caveman.md) · 종합 보고서: [`caveman-report.md`](caveman-report.md)

두 archetype 모두 헤드리스 `claude -p` CLI(`--output-format json`)로 실행. archetype 2의 OFF 데이터는 superpowers 실험에서 재사용.

## 판정

**저자가 `docs/HONEST-NUMBERS.md`에서 스스로 예고한 패턴이 두 archetype에서 정확히 반대 방향으로, 그것도 깔끔하게 재현됐다.**

- **Archetype 1(태그+필터 기능 추가, 세션당 출력 15,000+ 토큰의 "긴" 작업)**: 세션 전체 비용이 **15.1% 줄었다**. 저자의 "정상 응답이 1.5~2k 출력 토큰보다 길면 caveman이 돈을 아껴준다"는 경험칙과 정확히 맞아떨어진다. 응답 산문 길이는 37.6% 줄었다(저자 주장 "출력 65%"보다는 작지만, 이건 코드/커밋 로그처럼 caveman이 건드리지 않는 내용까지 포함한 세션 전체 출력이라 직접 비교는 무리).
- **Archetype 2(대소문자 정렬 버그 수정, 세션당 출력 ~3,500토큰의 "짧은" 작업)**: 세션 전체 비용이 오히려 **9.9% 늘었다**. 출력 자체는 10.9% 줄었지만(응답 산문 길이는 52.1%나 압축됐다), 스킬 로딩 고정비용이 그 절감분보다 컸다. 저자가 "터스한 코딩 Q&A에서는 순손실"이라고 명시한 바로 그 패턴.
- **정확성에는 두 archetype 모두 차이가 없었다.** Archetype 1은 OFF/ON 6세션 전부 테스트 통과(개수는 OFF 평균 8.7개 vs ON 평균 6.7개로 ON이 테스트를 더 적게 썼지만, 전부 통과했고 태그/필터링 기능은 동일하게 동작). Archetype 2는 OFF/ON 6세션 전부 `COLLATE NOCASE`로 근본 원인을 정확히 고쳤다.
- **품질 저하 신호 없음**: 두 archetype 12세션 전부 응답에서 부정어(안/못/없다 등)나 정확한 값(파일 경로, 커밋 해시, 테스트 개수)이 실수로 생략된 사례는 발견되지 않았다. 코드 블록·에러 메시지도 caveman 규칙대로 그대로 유지됐다.

**종합**: caveman은 "한 스킬이 모든 상황에서 이득"이 아니라 **작업 크기에 따라 부호가 바뀌는 스킬**이라는 저자의 주장이 이번 실험(각 archetype n=3)에서 그대로 확인됐다. 코드 생성처럼 출력이 긴 작업에서는 실제로 아꼈고, 짧은 버그 수정처럼 출력이 짧은 작업에서는 스킬 로딩 비용이 절감분을 넘어섰다. 응답을 짧게 만드는 효과 자체는 두 archetype 모두에서 뚜렷했다(산문 37~52% 압축) — "읽기 속도는 항상 이득"이라는 저자 주장도 일관되게 확인된다.

## 방법론 메모 / 한계

- **활성화**: `Agent` 도구 경로는 완전 실패(superpowers와 동일 양상), `claude -p`는 자연 훅 발동 확인(스모크 테스트에서 실제 caveman 말투 응답 확인). 본 실행 12세션(재사용 3 + 신규 9) 전부 `claude -p` 기준.
- **archetype 간 비교 불가**: archetype 1과 2는 작업 성격이 완전히 달라(기능 추가 vs 버그 수정) 절대 비용을 직접 비교하면 안 되고, 각자 자기 OFF 대비 %로만 해석해야 한다.
- **표본 크기**: archetype당 n=3. "긴 작업=이득, 짧은 작업=손실"이라는 방향성은 뚜렷하지만, 정확한 손익분기점(저자 주장 "1.5~2k 출력 토큰")을 검증하려면 더 다양한 작업 크기의 반복이 필요하다.
- **응답 길이 비교의 한계**: `result_len_chars`는 세션의 마지막 응답(요약문) 길이만 잰다 — 세션 중간의 툴 호출 서술이나 커밋 메시지는 caveman 영향권 밖(저자 스스로 "persisted outside chat: write normal prose — code, comments, commits"라고 명시)이라 포함되지 않는다.
- **archetype 2 OFF 재사용**: superpowers 실험에서 이미 `caveman: false`로 실행된 데이터라 그대로 유효한 대조군이지만, 그 실험 당시 caveman 활성화 여부를 별도로 진단하지는 않았다 — 다만 응답에 caveman 말투 흔적이 전혀 없다는 걸 육안으로도 확인할 수 있다.
